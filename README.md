# 金庸群侠：问道武林 · Wuxia Idle RPG

> 基于金庸武侠世界观的新国风**文字放置 RPG**（Idle RPG）设计与可运行前端 Demo。
> 核心规格：`开局无门派散人` + `1 主角 & 2 伙伴（三人行）` + `静态立绘 & 纯文字战斗表现` + `以《射雕》为起点，向《神雕》《倚天》《笑傲》《天龙》《侠客行》递进扩展`。

本项目包含两大部分：

| 目录 | 内容 |
| :--- | :--- |
| `docs/` | 13 册策划案：产品总纲、世界观、剧情库、数值模型、装备图鉴、门派机制、联网生态、前后端架构协议，以及伙伴获取与抽卡设计 |
| `frontend/` | 可独立运行的 Vue 3 Demo，内置本地模拟服务端（`mockEngine`），**无需后端即可体验全部玩法** |

---

## 快速开始

```bash
cd frontend
pnpm install
pnpm dev          # http://localhost:5173
```

启动后先选择开局：

- **新游戏**：Lv.1 白衣散人、0 伙伴，从主线 1-1 起步；伙伴靠剧情结识、在客栈养好感，送礼每日有数。
- **演武模式**：Lv.32、七位伙伴已就位、无任何限制，用于快速体验全部系统（**临时功能，后续版本移除**）。

开发时可用 `?mode=new` / `?mode=demo` 跳过开局界面。进度会自动存入浏览器，下次启动可「继续江湖」。

其他命令：

```bash
pnpm test         # 运行测试（vitest，约 5 秒）
pnpm test:watch   # 监听模式
pnpm build        # vue-tsc 类型检查（含测试代码）+ vite 生产构建
pnpm preview      # 预览构建产物
```

### 环境变量（`frontend/.env.example`）

| 变量 | 默认 | 说明 |
| :--- | :--- | :--- |
| `VITE_USE_MOCK` | `true` | 是否使用本地模拟服务端。**注意**：见下方「后端对接现状」 |
| `VITE_API_BASE_URL` | `/api/v1` | 真实后端 REST 地址 |
| `VITE_WS_URL` | `ws://127.0.0.1:8080/ws` | 真实后端 WebSocket 地址 |
| `VITE_LOCAL_SAVE` | `true` | 是否启用浏览器本地存档；设为 `false` 则不读不写，接入服务端存档后可关闭 |

### 伙伴怎么来（详见 `docs/12`）

25 位伙伴分三条路线：

| 路线 | 规则 | 例 |
| :--- | :--- | :--- |
| 剧情送 | 主线 / 支线到点直接入队，品质最高紫品 | 柯镇恶、穆念慈、马钰、少年郭靖 |
| 好感线 | 剧情只负责结识，在客栈养到好感 100 入队；橙品为「橙·下」资质 | 丘处机、瑛姑；洪七公须先呈齐「十道绝味」 |
| 抽卡 | 客栈「醉仙楼·结缘」获得 | 一灯大师、王重阳、哲别 |

- **形态与觉醒**：郭靖 / 黄蓉以紫品少年形态入队，洪七公等四位大侠以橙·下入队，好感 600 + 伙伴信物可觉醒为橙 / 红品。
- **醉仙楼·结缘**：单抽 100 / 十连 950 元宝；神品 1.5%、绝品 8%、上品 30%；60 抽起软保底、80 抽硬保底、十连保底上品；界面内含完整概率公示（含保底的综合神品出率约 2.4%）。求签式揭晓动画。
- **错过的伙伴**：免费的「故人寻访」约 30 天（每日线索有上限）；或花 150 元宝用「故人重逢令」直接重逢。

## 后端对接现状（给后端开发者）

战斗、离线结算、抽卡、掉落等均按**服务端权威**设计：客户端只负责渲染结构化结果。当前 Demo 中这些逻辑由 `frontend/src/network/mockEngine.ts` 模拟，数据契约定义在 `frontend/src/network/protocol.ts`。

需要注意：

1. **`VITE_USE_MOCK=false` 目前还不能直接连上后端。** `gameStore` 直接调用 `mockEngine`，`apiClient.ts` 中的 REST / WebSocket 封装尚未接入。接入真实后端前，需要把 store 中的这些调用改为走 `apiClient`。
2. **建议由服务端实现的逻辑**（`mockEngine` 中对应的函数可作为参考实现与对拍基准）：

   | 逻辑 | mockEngine 参考 | 协议 / 数据 |
   | :--- | :--- | :--- |
   | 战斗推演 | `simulateServerBattle` | `BattleReportDTO` |
   | 派生面板 | `computeDerivedStats` | `PlayerDTO` / `LoadoutPresetDTO` |
   | 抽卡与保底 | `rollGacha` | `GachaDrawDTO`；概率与卡池见 `config/gachaData.ts` |
   | 存档 | `gameStore` 的 `snapshot` / `applySave` | 可直接作为上传 / 下发格式 |

3. **抽卡、元宝、存档在本地都可被玩家篡改**（localStorage）。涉及真实付费前，抽卡结果、保底计数、元宝余额与存档必须以服务端为准，并记录审计日志（见 `docs/12` §十）。
4. `pnpm test` 中的数值与概率测试（`tests/balance.test.ts`、`tests/gacha.test.ts`）可作为服务端实现的验收标准。

## 技术栈

**前端**
- Vue 3.5 `<script setup>` + TypeScript 5.7
- Vite 6 · Pinia 3 · Tailwind CSS 4 · lucide-vue-next 图标 · Vitest 3
- 宣纸 / 玄墨双主题；水墨山水场景（随时辰昼夜、随地图换气候）；全响应式：宽屏三栏，平板双栏 + 右抽屉，手机单栏 + 底部导航 + 抽屉
- 人物、签筒、卷轴均为纯 SVG，零美术资源；抽卡动画预留了素材位（`config/gachaData.ts` 的 `GACHA_ASSETS`，需求清单见 `docs/12` §十五）

**后端（设计蓝图，见 `docs/11`）**
- 无轮询惰性离线结算 · 确定性战斗引擎 · 唯一真品神兵锁 · 和平 / 纷争 PK 区校验
- PostgreSQL / MySQL + Redis，REST + WebSocket 接口与战报 JSON 契约
