# 25 · 巡历战斗与按场掉落（已实装）

> 口径：巡历原先每 30 分钟一次遭遇，修行页没有战斗画面。现在改成每分钟打一场，修行页上演出来，每场都有收获。**每小时的产出与原先相同，请求数也没有增加。**

---

## 一、传统挂机游戏怎么做

| 做法 | 怎么做 | 代价 |
| :--- | :--- | :--- |
| 按时间结算＋演出画面（放置类主流） | 主界面一直在打，金币、经验往外蹦，实际收益是「时薪 × 时间」。装备隔一段时间抽一次，攒在宝箱里，领的时候才打开 | 服务器几乎没负担，领一次算一次 |
| 服务器实时打怪（传奇类） | 每只怪都是服务器上的一次事件 | 在线人数越多越吃力，离线一般只给经验 |
| 本地逐场模拟（单机放置） | 客户端一场场打，离线时快进 | 数据在玩家手里，联网游戏用不了 |

本作用第一种：**画面和结算分开**，胜负只是演出，入账按时间推算。

## 二、规则

| 项目 | 规则 |
| :--- | :--- |
| 节奏 | 每 1 分钟一场；每 30 场一场**精英**（即原先的遭遇）。黄河四鬼路引令使场次快 10% |
| 每场固定 | 纹银、真气各一份，等于当前时薪摊到这一场；运营的倍率活动照样折算。这是原有的打坐收益，只是拆成每场显示 |
| 每场几率 | 掉 1 件本关装备：25% ÷ 30（约 0.83%）；秘境宝箱：原几率 ÷ 30。掉落活动按倍数提高每场的掉件几率 |
| 精英固定 | 百炼玄铁 1、淬火石 1 |
| 离线 | 照常累计场次，最多 24 小时（1,440 场），回来一次结算 |
| 换关 | 不足一场的余量清零；各关的场次分开记，换回来接着数 |

**每小时产出对照**：真气、纹银不变；锻材仍是玄铁、淬火石各 2；装备平均仍是 0.5 件；宝箱平均不变。

## 三、画面

- 修行页舞台中央：左边是侠客与随行伙伴，右边是本关的小怪（每关一种小怪、一种精英，配在 `PATROL_FOES`）。打完显示「击退××· 纹银 +X · 真气 +Y」，精英另加锻材，然后赶路到下一场。
- 战斗用前后端共用的战斗模拟器、玩家当前的配装武学伙伴来算，招式和正式战斗一样。**胜负不影响收益**：先按本关首领折算小怪，模拟后一招就倒或久战不下就调小怪气血，打输了就削攻击和气血，最多试 6 次，让一场演 26~34 招（精英 32~40 招）、一定能赢。画面只演看得见的交手（掉血、回血、反伤、闪避、护盾），开场的被动加成不占时间。
- 同一场每次算出来一样（种子取角色、关卡、场次），切页回来接着演到当前这一步。一分钟内演不完的直接跳到结果。
- 上方一行：关卡、第几场、精英标记、**待清点 N 场**（上次结算后打完、装备与宝箱还没清点的场数）。点「收起画面」只留这一行，选择记在本机。
- 巡历攒满 24 小时后停在提示上，领取收益后接着打。
- 不逐场写进右栏日志；收功时记一条「巡历 打了 N 场，其中精英 M 场」。

### 一场怎么演

| 时刻 | 画面 |
| :--- | :--- |
| 登场（第 1 拍，精英 2 拍） | 对手从右边淡入；精英先打出「精英拦路」横幅 |
| 每一招（一拍 0.92~1.5 秒：按招数放宽，让交手占满一分钟，打完只留约 8 秒清点、赶路） | 出招的人**冲到对手跟前**再退回，0.17 秒时招式落下：对手被击退、红闪、飘字；有招式名的在头顶报招（品阶色），伙伴追击注「追击」 |
| 绝技 | 整幅压暗、打出招式横幅，出招者先蓄一口气（金光）再冲，0.38 秒落下，画面一震 |
| 暴击 | 白闪、画面一震，飘字放大写「暴击」 |
| 最后一招 | 对手被打飞、化墨散去 |
| 打完 | 「胜」字印盖下，纹银、真气（精英另有锻材）从倒下的地方冒出来；2.6 秒后上路：远山与路往后退，侠客一路小跑，直到下一场 |

**特效按兵器**（小怪没有招式，按画像的随身兵器）：

| 兵器（`combatForm`） | 特效 |
| :--- | :--- |
| 刀剑、斧 | 两道斜劈的剑光 |
| 拳、掌、腿 | 一圈掌风冲击波，外加八道气劲 |
| 枪、棍、弓、指、暗器、奇门兵器 | 一道直刺的光 |
| 爪 | 三道爪痕 |
| 音律、内劲 | 三圈涟漪 |
| 鞭 | 一道鞭影 |
| 挡招、护盾 | 一面护体罡气 |
| 闪避 | 闪开的人侧身一让，身前划过一道弧光 |
| 回气血 | 绿光往上冒 |

颜色看伤害：外功是银白，内劲、真伤泛金，毒是绿，流血是红；招式自带火、寒、水属性的，换成橙、冰蓝。

- **做法**：冲刺、击退、震屏、击飞用 Web Animations（位移量要现量）；特效、飘字、横幅是每一招重新挂上的元素，靠 CSS 动画在落招时刻播放。主要动 `transform`、`opacity`，交给显卡合成，不加刷新次数。
- 系统设了「减少动态效果」的（Windows 关了「动画效果」、远程桌面常是这样），不冲刺、不震屏、不走路，特效不划不扩散；招式名、飘字、特效、横幅改在原地淡入淡出。全局样式会把动画压成一瞬（`style.css`），这几样在 `wuxia.css` 里单独给回时长，否则一闪就没。
- 一招怎么演由 `frontend/src/config/patrolBeat.ts` 的 `patrolBeat` 从战报这一条推出来，不改战斗结果。

## 四、装备为什么不当场显示

当场显示就要让客户端提前知道结果（可以看准了再收、换关挑），或者定时问服务器（每人每小时多十来个请求）。所以装备与宝箱在**结算时由服务器掷**，客户端事先不知道；结算卡与日志写明掉在本关第几场。

## 五、请求与负载

| 项目 | 变化 |
| :--- | :--- |
| 请求数 | 不增加。场次由快照里的巡历锚点推算，固定所得是公式，客户端自己算 |
| 结算 | 按场掷几率，24 小时最多 1,440 次随机数；写库次数不变 |
| 流量 | 不增加，战斗画面在本地生成 |
| 客户端 | 每分钟模拟 1~4 次战斗，每次不到 1 毫秒 |

## 六、实现

- **规则**：`shared/trialStages.ts`：`PATROL_BATTLE_MS`、`PATROL_ELITE_EVERY`、`PATROL_DROP_CHANCE`；`advancePatrol` 返回 `{ battles, elites, firstBattle }`；`patrolBattleCount`、`patrolClock`（画面时钟，不改状态）、`rollPatrolDrops`（按场掷，记场次）、`patrolFoe`、`tunePatrolFight`。宝箱 `settlePatrolCaches` 在 `shared/player.ts` 按场掷。
- **存档**：`TrialStateDTO.stageBattles` 记各关场数，`stageEncounters` 记精英场数；旧存档按精英场数 × 30 折算。原先攒的遭遇余量按新节奏直接折成场次，不吃亏，不改数据库表。
- **协议**：`IdleGain.patrolBattles`（本次结算的场数，精英场数仍是 `forgeMaterials`），`TrialDropDTO.battle`（掉在第几场），`TrialPatrolStatusDTO.battles`。
- **服务端**：`server/src/game.ts` 的 `settlePatrol`。
- **前端**：`frontend/src/components/PatrolSkirmish.vue`（修行页舞台）与 `frontend/src/config/patrolBeat.ts`（一招怎么演），本地试玩的 `frontend/src/stores/trial.ts`，江湖邸报 `AwayReport.vue`，「江湖 · 三十关历练」的巡历卡显示已打场数与精英数。
